# MTT six-month organic acquisition and design-to-quote plan

Period: 2026-09-12 to 2027-03-12. Focus: qualified B2B packaging enquiries, not raw visit counts or guaranteed ranking.

## Daily task
Codex heartbeat `mtt-seo` runs at 09:00 Asia/Shanghai in this task. This does not depend on adding a GitHub workflow. The host/session and Codex allowance must be available. Read the last record before making changes. Check availability and important routes daily; run Lighthouse/static validation weekly or after relevant changes. Do not repeatedly retry an unavailable data connection. Record missing data explicitly.

## Measurement
Search Console is signed in under Chrome Hugo per the user; read access was verified on 2026-09-12. Local private baseline: work/growth/search-console-baseline-2026-09-12.md (excluded from git). GA4 access and the existing MTT web stream were verified on 2026-09-12; private baseline: work/growth/ga4-baseline-2026-09-12.md. Do not diagnose short visits from Search Console: engagement requires GA4 or equivalent evidence. Establish the first available full 28-day baseline: non-brand impressions/clicks, indexed important pages, query/page pairs. Compare complete 7- and 28-day windows, noting reporting lag. Track consent-respecting builder entry/start, solution selection, design review and accepted brief separately. An accepted form response is not an order.

## Delivery sequence
Month 1: correct availability, navigation, unclear guidance, form handoff, measurement; get real supplier-approved examples and specifications.
Months 2–3: improve perfume packaging, rigid boxes and inserts pages from actual query data and buyer questions. Publish at most two genuinely useful pages per week, with structure/material options, limitations, sampling and a relevant builder CTA. Avoid overlapping articles; update existing pages when they already answer the topic.
Months 4–6: expand only proven topics, improve pages with impressions but weak relevance/click-through, add permission-cleared real examples, review enquiry quality and conversion friction.

## Attract relevant buyers
Use one helpful page per distinct procurement question, interlink guides to the corresponding product and builder, and make the builder visible in the main menu. Prepare shareable examples for LinkedIn/industry communities, but do not post externally without authorization. Do not buy traffic/backlinks or create fake reviews/cases. A menu helps visitors discover the tool; it does not itself create Google demand.

## Guided product flow
Choose opening style → apply artwork and optional finishes → enter product size, quantity and market → review preview/specification → send contact details and artwork link → MTT engineering review and formal quote. Preserve downloadable briefs/projects, local saves, all structures, artwork positioning and exports. Uploaded artwork is local; a sharing link is optional and explicitly sent with the form. Automated file transfer/storage, delivery verification in the supplier inbox and a supplier quotation backend are not implemented. Never call this production CAD or promise an automatically generated formal price.

## Publishing gate
Read latest remote and protect local edits. Build and validate, review mobile/desktop and relevant interactions, preserve rollback commit, publish through the existing Pages package, verify live bytes. Avoid new recurring paid services. No daily forced title changes or article count targets. Summarize meaningful changes and weekly findings; remain quiet on unchanged checks. At period end report evidence and ask whether to continue content publishing.
